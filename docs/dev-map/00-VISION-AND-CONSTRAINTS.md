# 00 - 愿景与红线（VISION AND CONSTRAINTS）

> 本文件是 DirectorDesk 项目的最高约束。任何开发工作与本文件冲突时，以本文件为准。
> 仓库内 `docs/dev-map/` 是唯一权威上下文，聊天记录、外部文档均不作数。

## 一、项目定位

**DirectorDesk（3D 导演台）**：降低普通人制作 AI 视频的门槛，让非建模专业的人快速获得专业级分镜效果，成为连接剧本与 AI 视频生成的可视化中间层。

核心价值：「剧本 + 资源库 + 预设机位」降低 3D 使用门槛。

## 二、核心用户路径（最高优先级，永不偏离）

1. 写好 Markdown 剧本
2. 从资源库（本地 + 官方在线）获取角色和场景
3. 用预设机位快速摆镜头
4. 在类似思维导图的分镜画布中总览剧本、镜头和画面
5. 导出单镜头参考图或完整分镜总览，后续可调用文生图 / 视频 API

**开发顺序原则：优先用本地资源走通「剧本 → 摆镜头 → 分镜画布 → 导出」的完整闭环，再补在线资产库。** 任何时刻中断，项目都应是一个能走完主路径的可用产品。

## 三、目标用户

- 有剧本和分镜想法，但不具备专业 3D 能力的人
- 需要比纯文生视频更强可控性的创作者
- 希望快速产出可直接用于 AI 视频生成的专业参考图

## 四、P0 功能范围（只做这些）

1. **剧本系统**：Markdown 加载/查看/简单编辑；场次（Scene）与镜头（Shot）划分（语法见 `modules/script-format.md`）
2. **资源库系统**：本地导入 OBJ/GLB、离线可用；官方在线资产库（商店式浏览、一键下载、本地缓存，清单格式见 `modules/asset-manifest.md`）
3. **3D 导演台（简化版）**：模型导入显示、基础变换（位置/旋转/缩放）、轨道相机、预设机位（正视/侧面/过肩/俯视/特写等）、多相机切换、基础灯光预设
4. **镜头关联**：剧本镜头关联到相机/机位，支持快速跳转
5. **分镜画布**：根据剧本自动生成类似思维导图的 Scene/Shot 画布；剧本变化后动态重排；导演台调整后刷新关联 Shot 缩略图；点击镜头跳转相机（规格见 `modules/storyboard-canvas.md`）
6. **工程文件持久化**：场景布局、机位、关联关系、剧本路径及画布折叠状态保存为 `.ddproj`（格式见 `modules/project-file.md`）
7. **导出**：干净的单镜头参考图（透明 PNG、1080p / 2K）以及完整分镜总览 PNG；导出时隐藏应用 UI
8. **AI 接口预留**：只定义接口，不实现
9. **基础设施**：统一日志（控制台 + 文件）、高度模块化、CI

## 五、明确不做（P0 红线）

- 复杂骨骼动画编辑与关键帧系统
- 完整时间轴动画
- 自由绘制/任意连线画布（P0 的分镜画布只由剧本自动生成结构）
- 视频导出
- 高级材质与灯光编辑
- 自研 UI 框架
- 用户自行添加未审核的第三方 GitHub 源
- 软件内直接提交模型到官方仓库
- **Undo/Redo 系统**（P0 明确不做，Command 设计预留但不实现）
- Linux 支持（P0 只做 Windows + macOS，架构不引入平台强耦合即可）

## 六、平台策略

- **P0 平台：Windows（第一优先，先做先验证） + macOS**
- Linux 列入后续演进，不在 P0 验收范围
- CI 必须同时构建 Windows 与 macOS

## 七、开源与商业化

- 代码许可证：**MIT**（已确定，不再讨论；Phase 0 即放入 LICENSE）
- 官方资产许可证：**CC0**（个别资产可 CC-BY，清单中必须标注）
- 模式：Open Core。核心开源免费，后续通过官方资源包、预设、AI 增值服务商业化
- 社区贡献模型：通过 GitHub Pull Request 提交到官方资产仓库，维护者审核合并

## 八、后续演进方向（P0 之后，现在不做）

更多模型格式、第三方源（带审核机制）、资产库国内镜像源、文生图/图生视频 API 接入、镜头模板与智能辅助、简化版相机动画、Linux 支持、团队与云同步。
