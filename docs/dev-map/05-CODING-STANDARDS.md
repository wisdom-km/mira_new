# 05 - 编码规范（CODING STANDARDS）

> 本文件用于减少跨开发者、跨模型协作造成的风格与行为漂移。

## 一、语言与可移植性

- 使用 C++17；禁止依赖编译器私有扩展
- 目标编译器：Windows MSVC、macOS Apple Clang
- 跨平台逻辑优先使用标准库；平台差异封装在 Platform 或 backend 内
- 业务模块禁止直接使用 Win32、Cocoa、GLFW、bgfx、libcurl、spdlog API
- 所有内部文本为 UTF-8 `std::string`；平台编码转换仅在 Platform

## 二、命名与文件

- 命名空间：`DirectorDesk::<Module>`
- 类型、枚举：`PascalCase`
- 函数、方法：`PascalCase`
- 局部变量、参数：`camelCase`
- 私有成员：`m_camelCase`
- 编译期常量：`kPascalCase`
- 宏：`DD_UPPER_SNAKE_CASE`
- 接口以 `I` 开头，如 `IRenderer`
- 公共头放 `include/DirectorDesk/<Module>/`；实现放 `src/<Module>/`
- 一个主要公共类型对应一组 `.h/.cpp`；文件名与主要类型一致
- include 路径和文件名大小写必须与磁盘完全一致

## 三、格式与静态检查

- `.clang-format` 是格式唯一标准，不人工争论格式
- `.clang-tidy` 至少启用 bugprone、performance、modernize 中与 C++17 兼容的检查
- CI 将编译器警告视为错误；第三方代码警告不得污染项目目标
- 提交前格式化改动文件，不对无关文件做全库机械重排

## 四、所有权与生命周期

- 默认使用值语义和 RAII
- 独占所有权使用 `std::unique_ptr`
- 仅在真实共享生命周期时使用 `std::shared_ptr`，需要在评审中说明原因
- 非拥有指针/引用不得跨越其所有者生命周期；可空性必须显式
- 禁止裸 `new/delete`、手工资源释放散落在业务代码中
- App 拥有顶层服务和主生命周期；渲染资源由 Renderer RAII 包装

## 五、错误处理

- 可预期失败（文件、解析、网络、用户输入）使用项目统一的 `Result<T, Error>`/`Status`
- C++17 下由 Core 提供轻量实现；禁止各模块自创不同返回约定
- 编程错误使用断言；断言不得承担用户输入校验
- 不以异常作为正常控制流
- 第三方库抛出的异常必须在适配边界捕获并转换为项目 Error
- Error 至少包含稳定错误码、面向日志的技术信息和可展示给用户的简短信息
- 错误只记录一次：通常在掌握完整上下文的边界记录，避免层层重复日志

## 六、接口设计

- 公共接口最小化，依赖抽象而非 backend
- 头文件尽量前置声明，避免传播第三方头
- 公共类型不得暴露 bgfx、GLFW、curl、spdlog 具体类型
- 输入默认 `const&` 或轻量值；输出优先返回值/`Result<T>`
- 禁止布尔参数含义不明；使用枚举或描述结构
- 数据格式使用稳定字符串 ID，不把数组下标或指针当持久 ID
- 新增格式/服务优先注册扩展，不修改中心化条件分支

## 七、线程与异步

- 业务状态只由主线程修改
- 后台任务输入必须是不可变快照，输出必须是独立值对象
- 跨线程结果只通过规定的线程安全队列传递
- 禁止 detached thread、全局可变状态和后台线程调用 UI/Renderer
- 任务必须支持明确的生命周期；应用退出时可等待或取消

## 八、日志与隐私

- 仅通过 Core 日志宏记录
- 禁止记录密钥、完整认证头、用户私密剧本文本或模型二进制内容
- 路径可在 Debug 日志记录；面向用户日志应避免泄漏不必要的目录信息
- 网络错误记录 HTTP 状态、稳定错误码和目标主机，不记录敏感查询参数

## 九、测试

- 解析器、路径、数据迁移、预设算法、分镜布局/同步和错误分支必须有单元测试
- 文件测试使用临时目录，不依赖开发机绝对路径
- 至少包含中文、空格、非 ASCII 文件名用例
- 网络测试使用接口替身或本地固定响应，不依赖真实 GitHub
- 渲染使用小型技术测试与有限人工基线；避免脆弱的逐像素跨 GPU 比较
- 分镜布局测试使用固定输入验证顺序、无重叠和确定性；不得只靠截图人工检查
- 修复 bug 时先增加可复现测试，或在无法自动化时记录人工复现步骤

## 十、注释与 TODO

- 注释解释“为什么”和约束，不复述代码
- 公共接口用简短文档说明所有权、线程和失败行为
- TODO 必须包含原因和归属 Phase，例如 `TODO(Phase 8): ...`
- Phase 10 前不得遗留无归属 TODO、临时代码或静默 fallback

## 十一、Definition of Done

单个 Task 完成必须满足：

1. 行为符合当前 Phase 和对应契约；
2. 编译、格式、静态检查通过；
3. 相关自动测试通过；
4. 未越过模块边界或引入未批准依赖；
5. 错误路径与日志已覆盖；
6. 文档和 `03-CURRENT-STATUS.md` 在工作结束时同步更新。
