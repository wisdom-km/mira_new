# Markdown 剧本格式契约

版本：1.0（P0）

## 一、目标

使用普通 Markdown 表达场次与镜头，同时提供稳定 ID，保证镜头关联在标题改名后仍有效。

## 二、规范语法

```markdown
# 我的短片

## [scene:scene-cafe-day] 咖啡馆 - 日 - 内

场次说明写在这里。

### [shot:shot-cafe-001] 过肩

A 坐在窗边，看向街道。

### [shot:shot-cafe-002] 特写

A 的手指轻敲杯沿。

## [scene:scene-street-night] 街道 - 夜 - 外

### [shot:shot-street-001] 俯拍

雨中的空街。
```

### 结构规则

- 文档标题可用一级标题 `#`，不参与场次解析
- 场次必须是二级标题：`## [scene:<id>] <标题>`
- 镜头必须是三级标题：`### [shot:<id>] <标题>`
- 镜头归属于它前面最近的场次
- 标题后的 Markdown 正文一直持续到下一个同级或更高层标题
- 四级及更深标题视作正文，不产生结构节点
- 代码围栏中的 `#` 不参与标题解析

### ID 规则

- Scene ID 在文档内唯一；Shot ID 在文档内唯一
- ID 匹配：`[a-z0-9][a-z0-9_-]{0,63}`
- ID 是持久关联键；允许修改标题，不得随意修改 ID
- 新建场次/镜头时由应用生成 ID，建议格式 `scene-<uuid短码>`、`shot-<uuid短码>`
- 不使用标题文本、数组下标或行号作为持久 ID

## 三、容错和诊断

解析器必须收集诊断，而不是遇到首个问题即停止：

| 情况 | 行为 |
|------|------|
| 缺少标记的 `##` / `###` | 视为普通 Markdown 标题并给出提示，不创建节点 |
| 镜头出现在场次之前 | 不创建该镜头，给出带行号错误 |
| ID 不合法 | 不创建节点，给出带行号错误 |
| ID 重复 | 保留第一次出现，后续项不创建并报错 |
| 标题为空 | 创建节点，标题显示“未命名”，给出警告 |
| 空镜头正文 | 允许，给出提示级诊断 |
| UTF-8 非法 | 拒绝加载并显示文件错误 |

诊断至少包含严重级别、行号、稳定错误码和中文消息。

## 四、编辑与保存

- 读取和保存均使用 UTF-8（不强制 BOM；读取时容忍 UTF-8 BOM）
- 默认保留 LF/CRLF 风格，避免无意义整文件变更
- 简单编辑不应重排用户正文
- 应用创建的新节点必须立即写入稳定 ID 标记
- 删除仍被工程文件引用的镜头前需提示；P0 不实现 Undo
- 外部文件发生变化时不得静默覆盖，至少提示重新加载或另存
- 分镜画布严格按 Scene/Shot 在 Markdown 中的出现顺序生成
- 只有一次完整解析成功后才能发布新的剧本结构快照，避免画布显示半完成结构

## 五、非目标

P0 不解析人物、对白、情绪、时长、镜头运动等语义；这些内容都保留为普通 Markdown 正文。

## 六、最小测试集

- 中文标题与正文
- 多场次、多镜头
- 重复/非法 ID
- 镜头位于场次之前
- 代码围栏内伪标题
- CRLF、LF、UTF-8 BOM
- 含空格和中文的文件路径
