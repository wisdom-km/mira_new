# 02 - 开发路线图（ROADMAP）

> 所有工作必须按 Phase 顺序执行。未满足当前 Phase 的全部验收标准，不得实现下一 Phase 的功能。

## 一、通用门禁

每个 Phase 完成前必须同时满足：

- [ ] 本 Phase 的功能与自动化测试全部通过
- [ ] Windows 构建、测试通过；macOS CI 构建、测试通过
- [ ] 未引入超出 P0 或后续 Phase 的功能
- [ ] 模块依赖符合 `01-ARCHITECTURE-MAP.md`
- [ ] 新增公共行为已有测试；失败路径有明确日志和用户提示
- [ ] `03-CURRENT-STATUS.md` 已更新，已记录决策、已知问题和下一步
- [ ] 代码已经人工或模型复核，无遗留高优先级问题
- [ ] 在用户明确授权提交后，创建对应提交与 Phase tag

**Git 约束**：默认在 `main` 工作；短命分支仅在确有必要时使用。AI 不得自行提交、打 tag 或推送，必须获得用户明确授权。

## Phase 0：工程骨架、构建、日志与 Platform 基础

目标：得到可复现、可启动、可持续验证的空壳应用。

### Tasks

- [ ] 创建 `vcpkg.json`，锁定 builtin baseline 与依赖
- [ ] 配置 C++17、警告级别和 Debug/Release 构建
- [ ] 建立模块静态库/接口库骨架，验证依赖方向
- [ ] 封装 `Core::Log`：控制台 + 日期滚动文件
- [ ] 实现 Platform 路径与用户数据目录接口，内部统一 UTF-8
- [ ] 用 GLFW 创建窗口并处理关闭、尺寸变化与基础输入
- [ ] 集成 Dear ImGui docking，显示空工作区
- [ ] 建立 Catch2 测试入口
- [ ] 建立 Windows/macOS GitHub Actions 构建与测试矩阵
- [ ] 添加 MIT `LICENSE`、基础 `README.md`、`CONTRIBUTING.md`
- [ ] 添加 `.clang-format`、`.clang-tidy` 和基础编辑器配置

### 验收标准

- [ ] Windows 本地从干净环境按 README 可完成配置、构建、启动
- [ ] 应用打开带 ImGui docking 的空窗口并可正常退出
- [ ] 日志同时写入控制台和平台用户数据目录
- [ ] 含中文的用户数据路径测试通过
- [ ] Windows/macOS CI 构建和测试均通过
- [ ] 不包含任何场景、模型、剧本等业务实现

完成 tag：`phase-0-skeleton`

## Phase 1：bgfx 最小渲染、轨道相机与离屏技术验证

目标：尽早消除 bgfx、窗口集成、shader 编译和透明回读风险。

### Tasks

- [ ] 定义最小 `IRenderer`、渲染描述和错误返回类型
- [ ] 实现 bgfx 后端初始化、重置、帧循环和销毁
- [ ] CMake 自动调用 shaderc，为 Windows/macOS 编译 shader
- [ ] 渲染一个测试网格、基础材质和基础灯光
- [ ] 实现轨道相机：旋转、平移、缩放、窗口宽高比
- [ ] 实现 ImGui 视口与 bgfx 输出组合
- [ ] 实现最小离屏 framebuffer、RGBA 回读和 PNG 保存技术切片
- [ ] 验证透明背景 alpha 值，不将 UI 绘制进离屏目标

### 验收标准

- [ ] Windows 可交互查看测试网格，窗口缩放后画面正确
- [ ] macOS CI 至少完成编译与无窗口单元测试
- [ ] shader 全由构建系统生成，仓库不提交生成的 shader 二进制
- [ ] 可导出一张带正确 alpha 的测试 PNG
- [ ] ImGui 后端未侵入 `IRenderer`
- [ ] bgfx 资源在退出和错误路径中正确释放

完成 tag：`phase-1-render-camera`

## Phase 2：可扩展模型加载与本地导入

目标：用户可导入 GLB/OBJ，并在场景中摆放模型。

### Tasks

- [ ] 定义 `IModelLoader`、`LoaderRegistry`、`ModelData` 和错误模型
- [ ] 先实现 GLB 加载：网格、索引、节点变换、基础纹理与材质
- [ ] 再实现 OBJ 加载：网格、法线、UV、MTL 基础材质
- [ ] 处理缺少法线/UV、非法文件和不支持特性的降级路径
- [ ] 定义 Scene Node 与 Transform（位置/旋转/缩放）
- [ ] 实现文件对话框、本地导入 Command 和后台解析
- [ ] 在 UI 中提供选择与数值/操控器变换入口
- [ ] 加载结果只通过主线程结果队列写入业务状态

### 验收标准

- [ ] 示例 GLB 与 OBJ 均可显示和变换
- [ ] 新增格式只需实现并注册新的 `IModelLoader`
- [ ] 损坏或不支持文件不会崩溃，并给出可理解提示
- [ ] 中文路径中的 GLB/OBJ 可导入
- [ ] 加载期间 UI 不冻结，后台线程不直接访问渲染或场景状态

完成 tag：`phase-2-model-import`

- [ ] 定义 Camera、CameraManager 与 CameraPreset 数据结构
- [ ] 实现正视、侧面、过肩、俯视、特写预设
- [ ] 明确预设的目标对象、距离、视场角和退化行为
- [ ] 支持新增、删除、重命名和切换相机

## Phase 7：分镜画布与正式导出（核心闭环）

目标：走通“剧本 → 本地资源 → 预设机位 → 镜头关联 → 分镜画布 → 导出”的完整用户路径。

### Tasks

- [ ] Export 模块通过 `IRenderer` 离屏接口渲染
- [ ] 支持 1080p（1920×1080）与 2K（2560×1440）
- [ ] 支持透明或不透明背景
- [ ] 导出时排除全部 UI、选框和编辑辅助线
- [ ] 定义文件命名、覆盖确认和错误提示
- [ ] 为当前镜头导出；批量导出不在 P0 范围
- [ ] 按 `modules/storyboard-canvas.md` 实现 Storyboard 数据模型和确定性自动布局
- [ ] 实现类似思维导图的 Scene/Shot 卡片、父子连线、平移、缩放、适配全部和聚焦当前镜头
- [ ] 剧本结构变化后增量重建并动态重排；画布结构不得反向修改剧本
- [ ] 实现镜头选择在剧本列表、分镜画布和已关联活动相机之间同步
- [ ] 导演台相机、场景或灯光变化后，按规则标记关联缩略图失效
- [ ] 实现主线程防抖缩略图刷新、可见区优先和单帧单任务调度
- [ ] 缩略图与完整分镜导出均排除 UI、选框和编辑辅助线
- [ ] 以数据驱动绘制路径导出完整分镜总览 PNG，不截取应用窗口
- [ ] 对 200 个 Shot 验证布局、可见区裁剪和纹理缓存上限
- [ ] 执行一次端到端用户路径测试

### 验收标准

- [ ] 两种分辨率的尺寸、色彩方向和 alpha 均正确
- [ ] PNG 中不含任何 UI 或编辑标记
- [ ] 剧本新增、删除、重命名和重排后，画布自动同步且节点不重叠
- [ ] 点击已关联 Shot 可切换到对应相机；未关联 Shot 显示明确状态
- [ ] 连续调整导演台时 UI 不被缩略图刷新阻塞，停止操作后当前 Shot 自动更新
- [ ] 完整分镜总览 PNG 包含全部 Scene/Shot，不受折叠状态影响，并严格保持剧本顺序
- [ ] 画布不存在自由节点、任意连线或持久化手工位置功能
- [ ] Windows 与 macOS 导出结果通过自动/人工基线检查
- [ ] 从剧本加载、导演台调整、画布总览到单镜头/完整分镜导出的核心路径可完整演示

完成 tag：`phase-7-core-loop`

## 二、变更路线图的规则

只有出现以下情况才允许修改 Phase 内容或顺序：

1. 当前假设被可复现证据推翻；
2. 安全、数据损坏或跨平台阻断风险要求调整；
3. 核心用户路径发生由产品负责人明确批准的变化。

修改时必须同步更新 `00`、`01`、本文件及 `03-CURRENT-STATUS.md`，记录原因、影响和批准者。不得仅在聊天中改变路线图。
