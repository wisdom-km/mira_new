## 一、用户是谁、每天在做什么

| 项 | 结论 | 对界面的要求 |
|----|------|--------------|
| 用户 | 做 AI 短剧 / 短片的独立创作者或小团队导演。会写剧本，会用 Kling / Seedance 这类视频模型，**不一定会 Blender** | 不能长得像 3D 软件的调试面板；术语用影视的（景别、机位、取景），不用图形学的（FOV、节点、纹理索引） |
| 核心回合 | 读一个镜头 → 摆机位 → 看画面 → 导出参考图 → 下一个镜头。**一部 30 镜的短剧要重复 30 次** | 「切镜头 → 调机位 → 导出」三步必须最短、最稳定，键盘可完成 |
| 时间分布 | 估计 70% 在掌机（摆机位看画面），15% 置景，10% 编剧，5% 审片 | 掌机模式是主场；其余模式是它的前后台 |
| 最在意的画面 | **导出的那一帧**长什么样 | 视口必须所见即所得：比例、背景、构图与导出一致 |
| 最怕的事 | 不知道现在在哪个镜头、不知道改了什么、导出了不知道去哪了 | 当前镜头永远醒目；状态反馈就在操作旁边；导出后能一键打开 |

## 二、审计一句话结论

UI-PRO 把职责拆到了正确的位置，但**每个位置里的东西还是 Demo 时期的**：全部控件是 `SmallButton` 与纯文本、所有标题同一权重、开发者信息（`743 × 380`、`LIVE`、`BEAT MAP`、文件全路径）直接暴露、面板比例在 1024–1280 宽下互相挤压导致文字截断，而最关键的问题是——**视口看到的画面不是导出的画面**（比例随窗口变化、背景是蓝灰而非中性）。用户觉得「乱」不是因为区域多，而是因为**没有视觉层级、没有稳定锚点、没有专业术语**。

## 四、设计原则（本版五条）

1. **画面优先**：视口 = 导出画面。锁比例取景框、中性背景、辅助线可关；所有 chrome 为画面让路。
2. **镜头为轴**：当前镜头名出现在顶栏正中，`↑↓` / `[ ]` 切镜头；任何模式都能看到「我在第几镜」。
3. **稳定骨架**：左栏永远是「镜头表 + 场景」两段（审片也保留，可折叠）；底栏在不需要时**隐藏**而不是留一条空槽；区域位置不因模式而漂移。
4. **一处一职**：检查器每张面孔只回答一个问题（这个镜头用哪台相机？这个对象在哪？这个场景什么光？怎么导出？）。全局属性（灯光、导出设置）不放进镜头面孔。
5. **说导演的话**：术语表统一（第七节）；不出现像素尺寸、路径、英文缩写；空状态说「下一步做什么」。
