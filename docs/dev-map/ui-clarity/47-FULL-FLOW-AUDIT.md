> 2026-09-15。依据：Wisdom 提供的 22 张 **2576×1408** 实机截图（`v0.1.3` + 工作树 FND-10～56 + UIC U0/U1/U2 大部分），附 `步骤说明.txt`；对照 `src/UI/*.cpp`、`UiIcons.h`、`UiFonts.h` 当前代码。截图按 00→25 覆盖：空白启动、五个菜单、四模式、切镜、导出菜单、资源库在线、Skill 安装与运行、AI 检查器、审片点卡。

## 一、总评（一段话）

U0 把界面从「调试面板」拉到了「有骨架的工具」：取景框、中性色板、segmented 模式条、单主按钮、段头、术语都已落地，1280×800 下已无截断。但在 Wisdom 的 **2560×1440 / 100% DPI** 实机上暴露出三类新问题：**(1) 适配**——所有面板按百分比分配、字号固定 14px，导致左右栏各有 40–60% 空白、视口上下黑边各 ~115px、镜头条右侧 70% 空、整体像「小界面被拉到大屏上」；**(2) 位置**——AI 供应商设置（地址 / 密钥 / 三个模型名）作为全局配置被塞进镜头面孔和导出面孔各画一遍，资源库里常驻「安装示例 Skill」按钮和一段帮助文案，Skill 面孔把 `SKILL.md` 全文和 100 字符的缓存路径直接倒进检查器——专业软件里这些分别属于**首选项对话框**、**空状态 / 帮助**、**折叠详情**；**(3) 缺陷**——场景对象行只剩眼睛没有名字、主按钮 `▾` 渲染成 `?`、元数据输入框标签被裁成单字、无工程启动不再出现开始板、审片画布单列纵排只用 15% 宽度。

### 5.1 功能按钮与设置项的分界（Wisdom 2026-09-15 提出，本版规则）

一个按钮放哪，先问三个问题：

| 问题 | 答「是」→ | 答「否」→ |
|------|-----------|-----------|
| 它作用于**当前选中的东西**（这一镜、这个对象、这份剧本）吗？ | **功能按钮**：检查器 / 顶栏主按钮 / 右键菜单 | 往下问 |
| 改了它，**下次启动还该生效**、且与工程无关吗？ | **设置项**：`编辑 → 设置…` 对话框；存 `settings.json` | 往下问 |
| 它是**一次性的示例 / 教学**吗？ | **帮助菜单 / 空状态 / 开始板** | 回到第一问，多半是功能按钮 |

按这条规则把现状逐个归位：

| 现在的按钮 / 字段 | 类别 | 目标位置 | 任务 |
|-------------------|------|----------|------|
| 供应商 / 地址 / 密钥 / 三个模型名 / 「保存 AI 设置」 | 设置 | 设置 → AI 页 | UIC-49 |
| 「生成此镜图像」「生成此镜视频」 | 功能（作用于当前镜） | 镜头面孔 AI 段（保留） | UIC-49 |
| 界面缩放 / 视口背景 / 辅助线默认 / 默认导出分辨率 / 透明默认 | 设置 | 设置 → 常规 / 视口 / 导出 页 | UIC-49 |
| 网格 / 轴 / 安全框**即时开关** | 功能（当前视图） | 视图菜单（保留）+ 视口 HUD | — |
| 安装 Skill（本地文件夹 / 在线清单）、卸载、查看已装、默认分镜 Skill | **设置**（管理扩展） | 设置 → **Skills 页** | **UIC-59** |
| 「运行 Skill」 | **功能**（作用于当前剧本） | 编剧模式检查器「分镜」段 `[生成分镜 ▾]` | **UIC-60** |
| 「安装示例分镜 Skill」 | 示例 | 帮助 → 示例；资源库 / Skills 页空状态 | UIC-44 / UIC-51 |

**为什么 Skill 从资源库搬走**：资源库的心智是「拖到场景里的东西」；Skill 拖不进场景，混排只会让用户在网格里找不到模型、又不知道 Skill 卡片能干什么。分发管线（官方清单 `format=skill` → 下载到本机缓存，FND-32/33）**不变**，只是 UI 宿主从资源库网格换到 Skills 设置页——`Asset::Library` 仍索引它，`LibraryPanel` 按 `kind` 过滤掉即可。`../foundation-upgrade/32` 第 41 行「资源库多一个类别 Skills」由本节改写。

**关于左栏 tab 化与 UI-PRO 区域 ID**：`LEFT_HIERARCHY` 与 `LEFT_LIBRARY` 两个区域 ID 与窗口 `###Hierarchy` `###Library` **不改名**；tab 化只是把两个窗口 dock 进同一节点并让 tab 条可见（该节点不设 `AutoHideTabBar`），再把「场景」从 `###Hierarchy` 内的第二段升为同节点第三个 tab（新窗口 `场景###SceneTree`，属于 `LEFT_HIERARCHY` 区域）。这是 dock 层面的重排，符合 `../ui-pro-upgrade/23` 三「区域 ID 不改」的要求；需在 [`41`](41-AREA-CONTRACT-V2.md) 补一节说明。
